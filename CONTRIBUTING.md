# Submit a community project

Add your project to the README table and include the following evidence in your pull request:

- **Project and author:** name, GitHub handle, and contributor credits. Submit your own work or explain your contribution and permission to feature it.
- **Source:** public repository URL and license location. Preserve attribution for any upstream work.
- **Demo:** a short video, screenshots, or a live demo showing the main user flow.
- **Setup:** supported JDK, Android SDK, build commands, configuration requirements, and a tested commit. Link to these instructions in your repository.
- **Maturity:** learning exercise, prototype, maintained app, or archived project. State what is incomplete.
- **Engineering lesson:** one concrete decision, its tradeoff, and what you learned. For example, explain why you used a local cache and how you handle stale data.
- **Validation:** commands/device checks actually run and known limitations. AI projects should state model/provider requirements and any usage costs.

Do not commit credentials or user data. Use example configuration and explain how a learner supplies their own values.

Fork this repository, add one project per branch, and open a pull request. Keep the existing table format. Follow the [Code of Conduct](CODE_OF_CONDUCT.md). A listing is a community showcase, not a guarantee that the project is secure, maintained, or production-ready.
